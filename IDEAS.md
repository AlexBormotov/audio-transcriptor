# Идеи по улучшению приложения

Краткий список направлений развития: голосовой ввод, горячие клавиши, дизайн, функции и надёжность.

---

## Ваши идеи

### 1. Транскрипция «по кнопке» (псевдо-реального времени)

- Одна кнопка в интерфейсе: **нажал — запись**, **нажал снова — стоп**.
- Распознанный текст **добавляется в то же поле**, где показывается результат обычной транскрипции файлов (или вставляется в позицию курсора — на усмотрение реализации).
- По смыслу это не потоковый Whisper «слово за словом», а **короткие сегменты**: запись с микрофона → один проход модели → текст в окно. Так проще внедрить и меньше нагрузка на GPU/CPU.

**Плюсы:** понятный UX, мало элементов управления, переиспользование текущего окна результата.

**Замечания:** нужен индикатор «идёт запись»; стоит подумать о таймауте тишины и уровне громкости (опционально).

### 2. Режим «удержание — диктовка в буфер — вставка в активное окно»

- Запуск по сочетанию клавиш, например **Ctrl+Shift+S** (конфликты с другими программами лучше проверить и сделать настраиваемым).
- **Пока клавиши зажаты:** идёт запись; по завершении сегмента (или по отпусканию) текст попадает в **буфер обмена** и/или сразу пытается **вставиться** в окно под фокусом Windows, где стоит курсор.
- Обязательно `**try` / `except`**: вставка через UI Automation / `SendInput` / эмуляцию Ctrl+V может не сработать (права, защищённые поля, удалённый рабочий стол, игра в полноэкране и т.д.). В этом случае — только буфер обмена и уведомление пользователю.

**Плюсы:** удобно диктовать в браузер, мессенджер, IDE без переключения на окно транскриптора.

**Риски:** глобальные хоткеи на Windows требуют аккуратной регистрации; политики безопасности; доступность для пользователей с другими раскладками.

## Дополнительные идеи (функции)

- **Потоковая транскрипция** (настоящий real-time): отдельная задача — VAD, буферизация, возможно whisper-live / chunked inference; сложнее, но ближе к «как в Zoom».
- **Выбор устройства ввода** в настройках (микрофон по умолчанию vs конкретное устройство).
- **Язык по умолчанию** для голосового режима + «авто» как сейчас для файлов.
- **Пауза между фразами:** при длинном удержании кнопки склеивать несколько коротких распознаваний в один блок или разделять абзацами.
- **История сессий** голосового ввода (локально, без облака) — последние N фрагментов.
- **Экспорт:** один клик — в файл `.txt` / копировать всё; для голосового режима — «копировать последний фрагмент».

## Дизайн и UX

- Чёткая **визуальная индикация записи** (пульсирующая точка, цвет кнопки, таймер длительности).
- **Краткие подсказки** под кнопкой или в «первый запуск»: как работает push-to-talk и хоткеи.
- **Тёмная/светлая тема** или следование системной теме Windows.
- **Масштаб шрифта** в поле результата (Ctrl+колёсико или слайдер).
- Минимизация в **трей** с иконкой «идёт запись» — чтобы не закрывать окно случайно.

## Производительность и качество

- Для голосового режима по умолчанию **меньшая модель** или быстрый пресет, с подсказкой «для лучшего качества выберите …».
- **Ограничение длительности** одного нажатия (например 5–10 минут), чтобы не забивать память длинным буфером.
- Опционально **шумоподавление** перед отправкой в модель (если появится зависимость — оформить как опцию).

---

## Технические и безопасность

- Глобальный хоткей: библиотека уровня `**keyboard` / `pynput` / WinAPI** — оценить лицензии, антивирусные ложные срабатывания, работу от имени администратора.
- **Настройка сочетания** в UI + сохранение в конфиг (чтобы не конфликтовать с IDE пользователя).
- Логирование только **без чувствительного текста** в файлы логов; голос не сохранять, если пользователь не включил «отладочную запись».

## Установщик и дистрибуция

- Ярлык «**голосовая заметка**» или отдельный маленький режим окна только с кнопкой (опционально).
- Упоминание в **README**: нужны права на микрофон в Windows, исключения для корпоративных политик.

### Встроенная доставка зависимостей (идея)

- **ffmpeg:** если при установке (или первом запуске) `ffmpeg` **не найден** в `PATH`, установщик **Inno Setup** может:
  - положить статический **ffmpeg.exe** (и при необходимости сопутствующие dll) в подкаталог рядом с приложением, **прописать PATH только для пользователя** или заставить приложение вызывать `ffmpeg` по **абсолютному пути** (так надёжнее, чем рассчитывать на системный PATH);
  - либо показать **галочку** «Установить ffmpeg вместе с программой» и скачать/распаковать заранее положенный в дистрибутив архив (учесть лицензию LGPL/GPL сборки ffmpeg).
- **NVIDIA / GeForce / GPU:** идея в том же духе — если обнаружена **видеокарта NVIDIA**, но для работы PyTorch с CUDA **не хватает драйвера** (или он слишком старый), установщик мог бы:
  - предложить **открыть страницу загрузки драйвера** или запустить **офлайн/онлайн-инсталлятор NVIDIA** — с явным согласием пользователя (UAC, перезагрузка);
  - **не обещать «тихую встройку CUDA» как маленький пакет:** полноценный драйвер NVIDIA весит сотни МБ, распространение связано с **лицензией NVIDIA** и политикой обновлений; разумнее **не вшивать драйвер в .exe** без отдельного юридического и UX-решения, а дать мастер «У вас GeForce, для ускорения нужен актуальный драйвер → [Скачать с nvidia.com]»;
  - уточнить в тексте установщика: **GeForce Experience не обязателен** для CUDA; нужен именно **дисплейный драйвер** под чип. Отдельный **CUDA Toolkit** для запуска уже собранного приложения обычно **не нужен**, если в сборке уже есть `torch`+CUDA wheels.
- Практичный компромисс: **ffmpeg** — реально «поставить с программой»; **NVIDIA** — **проверка + ссылка или запуск официального инсталлятора**, опционально проверка версии драйвера через WMI/registry.

## Окно проверки внешних компонентов (доработка)

Идея: при старте или по кнопке «Проверить окружение» показывать **одно окно со списком того, чего не хватает**, с коротким текстом и **ссылкой на руководство** (официальный сайт или ваша страница в README / Wiki). Не блокировать запуск без необходимости: например, без ffmpeg можно разрешить только аудиофайлы, а видео — серым с подсказкой.

### Поведение UX

- Кнопки: **«Открыть ссылку»** рядом с каждым пунктом, **«Скопировать команду проверки»** (например `where ffmpeg`, `python -c "import torch; print(torch.cuda.is_available())"`).
- Не путать пользователя: **Whisper / faster-whisper «из коробки»** дают *модель и код* инференса, но **железо и системные утилиты** (ffmpeg, драйвер NVIDIA) с ОС всё равно должны быть на месте для соответствующих режимов.
- Если всё в порядке — короткое «Окружение в норме» или иконка в статус-баре без модального окна.

## Приоритизация (условно)

1. Кнопка «запись / стоп» + вывод в существующее поле — **высокий** приоритет, относительно простая ценность.
2. **Окно проверки зависимостей** (ffmpeg, GPU/CPU, по необходимости VC++) — **средний**: сильно снижает саппорт «ничего не работает».
3. Индикатор записи и выбор микрофона — **средний**.
4. Ctrl+Shift+S + вставка в фокус — **средний/высокий**, но больше краевых случаев и тестов.
5. Настоящий streaming — **низкий** как первый шаг, **высокий** как долгосрочная цель.
